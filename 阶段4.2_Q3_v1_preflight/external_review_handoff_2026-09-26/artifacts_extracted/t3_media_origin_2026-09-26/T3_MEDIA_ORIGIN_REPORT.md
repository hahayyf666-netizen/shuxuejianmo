# T3 媒体起点核验报告

**阶段**：4.2 Q3 v1 preflight / T3 Media Origin Validation  
**版本**：`q3-t3-media-origin-v1-2026-09-26`  
**本报告状态**：T3 完成；随后执行 4.5 内部验收并停止。  

## 1. 目的与边界

T3 只验证附件4短视频与 T2 候选来源媒体之间是否存在可复核的媒体起点关系。验证使用附件4 MP4 的原始音轨和视频 presentation PTS：

- 音频：对整段来源音频与附件4音频做归一化互相关，并要求峰值、峰值间隔、两半段一致性同时满足冻结阈值；
- 视频：从附件4视频的 0.2、0.5、0.8 位置取解码帧，按 presentation PTS 在候选来源视频中检索，要求至少两个像素相关通过且起点偏差范围满足阈值；
- 身份结论：音频和视频两个门都通过才记为 `media_identity=PASS`。

T3 是**媒体导航证据**，不是官方特征提取器 provenance，也不改变 Q3 当前解释合同。T3 不读取标签、预测、Shapley 或 IG，不运行模型，不把任何样本的正式解释映射从 `index_only` 升级为秒级或帧级证据。

## 2. 冻结范围

T2 候选表中具有 11 字符 YouTube ID 形状的 15 条样本进入本轮媒体核验。样本 `06、09、10、11、16` 的候选 ID 不满足该形状，因此记录为排除，不把它们误报为来源媒体失败。

## 3. 结果汇总

| 指标 | 结果 |
|---|---:|
| 候选样本数 | 15 |

| 视频门通过 | 9 |

| 正式 Q3 audio/vision mapping | `index_only`（保持不变） |
| 模型或预测运行 | 否 |

完整媒体起点通过的样本：`01、02、04、07、08、14、15、17、19`。

部分或阻断情况：

- `03、05、12、20`：来源媒体元数据/下载探测未满足 T3 可复核条件；
- `13、18`：音频起点门通过，但视频门未通过，因此按冻结身份规则不记为完整媒体起点通过；
- `06、09、10、11、16`：因候选 ID 形状不满足预先冻结的导航范围而排除。

这些结果只说明在本轮候选和门限下的媒体起点证据覆盖率，不证明未通过样本不存在来源，也不证明官方特征由该媒体链生成。

## 4. 典型核验

样本 `02` 复用了 T1 已核验的来源媒体，音频互相关和视频多帧 PTS 检索均通过；音频与视频起点估计相互接近。该结果支持“附件4片段可以回溯到候选来源媒体”的导航结论，但仍不推出官方 COVAREP/FACET 行的原始采样窗口。

## 5. 与正式解释输出的关系

正式 Attachment4 解释仍按冻结合同输出：

```text
text  = verified_text
audio = index_only
vision = index_only
```

原因是 T3 只建立媒体层起点证据，尚未把每一条官方音频/视觉特征行与附件4本地时间坐标建立逐行、可复核的合同映射。尤其 T2 已知的视觉行非唯一/视觉链不可用样本仍必须保守处理。任何秒级音频区间、视频关键帧或“官方特征行由该时间窗提取”的表述均不由 T3 授权。
