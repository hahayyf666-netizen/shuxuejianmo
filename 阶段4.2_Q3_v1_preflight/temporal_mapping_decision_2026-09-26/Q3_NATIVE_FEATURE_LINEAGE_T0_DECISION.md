# Q3 T0 原生特征来源链：独立可行性判断

日期：2026-09-26。状态：**方案核验，未执行 T0**。不改 B0/B1、Shapley、conditional IG、已完成的 valid120、现行映射状态或旧 C-1/C-2/C-3/C-4 工件；不做附件4预测。

## 决策

同意将下一次受控诊断的核心改为 `official aligned[i] → official unaligned[j] → 原素材时间`。前一段已经由 C-2 的本批附件逐维匹配验证：音频 564/564 个内容位置，视觉 523/564；后一段仍缺失。它避开了直接把文本词时间赋给音视频行的错误跳步，也比仅按时长比例或 CKA 推测更有希望形成模型归因与原素材之间的证据链。

**决定：有条件允许一次小范围 T0，但不接受“同维重提后一旦最近邻相似就自动通过”的实现。** 本次只作决策复核；应在预先冻结输入、候选提取流程、数值容差、阴性对照和停止条件后执行。现行音视频解释继续 `index_only`，T0 结果通过审核前不得升级。

## 新建议成立的部分与仍待证明的部分

- 官方 CMU-MOSEI SDK 的 [数据定义](https://github.com/CMU-MultiComp-Lab/CMU-MultimodalSDK/blob/main/mmsdk/mmdatasdk/dataset/standard_datasets/CMU_MOSEI/cmu_mosei.py)列有 COVAREP、FACET 4.2、OpenFace_2 的计算序列；[处理示例](https://github.com/CMU-MultiComp-Lab/CMU-MultimodalSDK/blob/main/examples/mmdatasdk_examples/full_examples/process_mosei.py)利用序列区间对齐、填补缺失并生成长度50的张量。COVAREP、FACET 因而是合理候选，不是这批附件的已证明来源。
- [COVAREP 官方提取脚本](https://github.com/covarep/covarep/blob/master/feature_extraction/COVAREP_feature_extraction.m)实际拼接了 74 个声学分量，支持优先核验音频候选；默认采样间隔是 0.01 秒，允许参数化。脚本开头“35维”的旧注释与后面的分量列表不一致，不能只看注释。附件4音频有效长度约为视频每秒20行，因此具体采样/重采样规则仍要独立验证，不能把 20 Hz 代理网格当来源记录。
- C-4 的 openSMILE 25维与 MediaPipe 52维不能逐维重建官方 74/35维。其“0行严格验证”不排除别的提取器或官方带时间的计算序列能匹配。
- 官方 SDK 示例以 GloVe 对齐；本批附件4的文本连续特征已由 C-4 精确重建为 BERT 路径。故 SDK 示例不能直接证明本批 `aligned_50` 的完整生成流程。附件2公共同名 PKL 的整文件 SHA 与本批不同，也不能反向证明本批音视频逐行不同；只能靠**同样本数值行**检验。
- 视觉35维的家族候选是 FACET，但 SDK 同时列有 OpenFace_2。维数、名称或论文中常见组合均不足以确定本批视觉行。FACET 的可复现环境、版本和逐帧 PTS 当前没有在本地确认；样本13/16另外有41个 aligned vision 内容行未能匹配同批 unaligned 的唯一有效行。
- 本机当前命令路径未发现 MATLAB/Octave；不能把“可以运行 COVAREP MATLAB 脚本”视为已通过的环境条件。

## T0 的最短顺序与停止门

1. **先固定样本和证据**：选 `02、03` 为普通正例，`07` 为超长截断情形，`13、16` 为视觉异常情形；这是依据 C-2 结构、在看任何附件4预测前选择。五条均核 MP4、aligned/unaligned PKL SHA，禁止用标签或模型输出挑样。`13/16` 的视觉只做异常判定，不能将它们计入视觉“应有唯一来源行”的通过率。
2. **先试已有带区间的同源计算序列**：若能取得对应样本的官方 COVAREP/FACET CSD 或其他可核身份的带时间源序列，先做同维逐行数值匹配。这比重新运行提取器少一个版本、解码、预处理差异。C-3 曾未能取得可用的本批对应 CSD；如果仍不可用，直接记录并转下一项，不展开无限来源搜索。
3. **再做受限重提**：音频只用预先冻结的一个 COVAREP 实现/版本、解码命令、presentation 音轨、采样率、特征采样间隔、通道顺序和浮点处理；从原 MP4 重建带采样中心及实际支持窗的74维候选。视觉仅在有明确可运行的35维候选及可保存实际解码 PTS 时执行；不可因为维数为35就命名 FACET 或把 OpenFace、MediaPipe 输出硬投影到35维。
4. **数值匹配须可证伪**：先按 dtype/保存精度固定逐维容差。对官方 unaligned 行与候选原生行逐行计算最大绝对误差、归一化误差、次近邻间距、唯一匹配比例、索引单调性；加同一视频错位/倒序和不同视频阴性对照。不能只凭余弦、CKA、序列长度相近或高维最近邻唯一就宣布通过。不得在这五条上调 offset、DTW、学习投影或逐样本改参数直到吻合。
5. **时间语义单独检查**：候选行若匹配，还需核候选时间相对 MP4 edit list 与解码 PTS 的定义。COVAREP 的采样中心不等于所有74通道共享的精确音频支持窗；只能报告有根据的时间分辨率/范围。视觉必须回看候选实际解码帧，而非 `frame_index/fps`。
6. **仅匹配行继承**：`aligned[i] → unaligned[j]` 的 C-2 记录和 `unaligned[j] → 带时间候选[r]` 都通过时，才可给该行 `verified_reconstructed_time`，同时声明 `official_extractor_log=unavailable`；13/16视觉无法通过第一段链，继续 `index_only`。未匹配、重复最近邻、数值或时间门失败的行均保留 `index_only`。达到预设失败条件立即停止，不扩到20条。

## 为什么“成功后整条链闭合”仍需逐项限定

即便 T0 音频通过，视觉也可能不通过；即便普通视觉行通过，13/16 的41行仍无 C-2 唯一来源。C-2 的 564 个位置只涵盖附件4的文本内容位置，不自动覆盖 `[CLS]`、`[SEP]`、padding 或最终 IG 选中的所有位置。正式 Q3 解释卡必须按**被归因的具体行**标注映射状态；不能把样本级或模态级成功率写成全部关键证据已定位。音视频源时刻与同位置文本词时刻是否一致，则作为额外语义交叉检查，不能反向制造主时间映射。
